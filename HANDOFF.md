## Gotchas
- Descenders get cut by clips sized to the line box (line-height ≤ 1): `[data-hover] .hv` resting clips are `inset(-0.3em 0)` for that reason (was `inset(0%)`, cut the g of "Night"), and the About name's SplitText masks (`overflow: clip`) are reverted once it has risen (they cut the J of "Ranjan"). Any new masked display text with j/g/y needs the same.
- `.ask` colours must stay on `currentColor` (`--soft`/`--hair` in `.ask`), not `--ink`/`--ink-soft`: `.ask` inverts the palette just by setting `background: var(--ink); color: var(--bg)`. `.ask-dialog` must be anchored to one edge (`inset: 0 0 auto`, phones `auto 0 0`): with `inset: 0` a modal dialog stretches to its max-height and the empty state gets a big gap. Never set `display` on `.ask-dialog` itself (author styles beat the UA `dialog:not([open]) { display: none }`).
- Not verified: real trackpad momentum, physical touch / iOS Safari, adaptive render-scale on weak GPUs, 120 Hz feel.
- Render loops (`DiscGallery.frame()`, `ScrollNext`): keep the rAF handle set for the life of the loop. Clearing it at frame start caused duplicate loops (30 fps lock).
- Scroll-next section needs `overflow: clip`, not `hidden`, or `position: sticky` breaks.
- Env map canvas must stay `NoColorSpace`. Tagging it sRGB darkens the discs.
- Disc label rim text is every metadata value joined. It now shrinks to fit (down to ~65% size), so very long metadata gets small rather than overlapping. Still keep values short.
- Supplied `image` labels get the rim credits printed on top by default (`art.rim: false` to disable) and a title if `art.title: true` (`drawSuppliedLabelText` in `src/art/placeholderArt.ts`, called from `labelTexture` in `discAssets.ts`). The overlay title is capped at 50% label width so it clears the rim.
- Preloader counter (`src/motion/Preloader.ts`): each drum rolls (`CFG.digitRoll`) to its digit of floor(P·100) when it changes, so carries roll with the ones digit. Instrument Serif's figures ignore `tabular-nums` (a "1" is ~20 px vs "0" ~40 px at 96 px), so the tens/hundreds cells resize to their current digit (`DIGIT_W`, `fitCell`); the ones cell stays at the full measured width so the centred counter doesn't jitter. Don't let higher drums roll ahead of the ones (the old "last 4 units" carry read as 106–109 before 100). Driven every frame by progress P (eased 2.85 s clock, soft-capped while cover textures load, rate-limited). It no longer uses the reference's 4 random "beats" (user found the jump-and-hold unsmooth); don't reintroduce them. In headless Playwright the textures take ~10 s, so the counter creeps slowly there; that's the load cap, not a bug.
- Preloader orbit (`place()` in `Preloader.ts`): the ellipse radii shrink to fit the room above/below and left of the disc; don't go back to clamping x/y alone, which flattened the top of the arc into a straight line (and the start into a flat run along the bottom).
- The preloader left label shows `site.name` only. Adding the long section label there made it run into the disc.
- Build item URLs with `projectUrl(p)` (`src/content/projects.ts`), not `/work/${slug}`, so a `Project.href` override is respected.
- Detail-page `links` that start with `/` go through `go()` (page transition). Anything else is a plain anchor, and `http…` opens in a new tab.
- Disc label art: the centre hub masks a circle of radius 12% of the image width (`0.5 × max(holeSize, hubSize)`). Keep the subject outside it, or use `art.{scale,x,y}` to shift it.
- Detail-page body lines are SplitText'd per element, not on the container (splitting the container flattened paragraphs). Selector covers lede, `.about__text` children, body list items, rail head, rail `li > p` (not the `li`, which holds a `.rule` span) and the coda. Body paragraphs have `break-inside: avoid` in the 2-column layout; don't remove it, or a paragraph split across columns breaks SplitText's line grouping. Side effect: columns can end unevenly when one paragraph is long (Marketing Associate).
- Gemini free tier on this key: only `gemini-3.8-flash` is available (every other model 404s for new users), and it allows 20 requests/day per project (so ~40/day across both keys). It also returns 503 "high demand" at times (handler retries twice), and sometimes fails mid-stream after a 200 (`UNAVAILABLE` event; the answer ends with `errors.cutOff`). Free-tier answers took 10–15 s end to end on 2026-09-28. Testing burns the daily quota fast. Don't add `temperature`/`top_p`/`top_k` back: 3.6+ models ignore them and Google says they'll be rejected (removed from `chat.ts` 2026-09-28). Two keys from two projects on one app is what Google restricts as "quota circumvention" (forum reports, 2026); the user has been told and hasn't decided yet. The key never bills unless billing is enabled on its Google project.
- Chat server code must not use Node-only APIs (`server/*` has to run on Vercel/Cloudflare too); Node glue lives only in `vite.config.ts`. `@types/node` is referenced there only, not in `src`.
- New content fields must be added to both `src/content/types.ts` and `src/admin/schema.ts`, or the admin can't edit them (unknown keys survive saves untouched but get no form field).
- Keep the admin's `lazy()` in `src/admin/route.ts`, not `App.tsx`: saving content hot-reloads App.tsx, and a lazy() created there remounts the admin and drops unsaved edits in other sections.
- Admin clean-up on save drops empty optional fields (that's how "empty hides the row" works) and collapses a one-line facts value to a string.
- `.about` is taken by the detail page's description section. The About page uses the `.profile` prefix.
- Window chrome bevels must use `--edge` (always black), not `--ink`: at night `--ink` is light, so the outer bevel and the hover's hard shadow would turn into a light outline. Hardcoded `rgba(0,0,0,…)` text colours go dark-on-dark at night; use `--ink-muted`/`--ink-soft` or scale with `var(--night)`.
- The contact prompt's `transition` also has to carry `[data-hover]`'s `transform 0.45s` spring, since it replaces that declaration.
- Night colours are duplicated on purpose: `NIGHT.fog` must equal the night `--bg` in `global.css` (also used as the night `theme-color`); the localStorage key `night` is repeated in `index.html`'s pre-paint script.
- Lamp glint: the bulb's mirror highlight on the label moves with `NIGHT.offset`, not `aim`. Moving the lamp back (−z) or higher moves it up toward the hub and then onto the title (the old [-0.85, 1.05, -0.1] did; so did touch [-0.4, 1.15, 0.1]); more −x moves it left. To move the focus, move `offset` and `aim` together. Check with `node reference/tools/night-shot.mjs <prefix> [w] [h]` (own Vite on :5198, night saved, shots of disc 0, disc 1 and a lamp close-up into `validation/`).
- `THREE.SpotLight` defaults to position (0, 1, 0). In `Lamp.ts` it's reset to the bulb centre; without that it sat behind the shade and lit its back and the cord.
- The lamp's spot and fill lights stay in the scene at zero intensity by day. Adding/removing it changes the light count and recompiles every disc material.
- Disc logos are drawn as `<img>` onto a canvas, so an SVG needs intrinsic `width`/`height` (the ANSR original only had a viewBox; the variants add it), and `currentColor` resolves to the root `color` attribute, not the page. Recolour by editing the SVG file, not in code.
- Agent screenshots must stay ≤2000 px per side or the session dies with an ImageValidationError (it killed the night-mode session). Use `page.screenshot({ scale: 'css' })` or small clips at DPR > 1.
- Game embed: the game's own focus() calls bounce focus through the parent window (focus then straight back to the iframe), so the pause-on-window-focus check waits 60 ms and only pauses if `document.activeElement` is no longer the iframe. Without that, loading showed "Click to resume" right after Play. The game (cross-origin, no postMessage API) doesn't pause when the cover returns; it keeps running under it. A pause-on-`blur` in the game repo would fix that. Don't put the enlarged window's centring on CSS `translate`: it fought GSAP's FLIP transform and sent the window along a wrong path. `.site__view` sets 16:10 later in the file, so the game's 16:9 needs the `.game__win .game__view` specificity. At 374 wide the game's own layout crops its title screen slightly at the top. The game site must keep allowing framing (no X-Frame-Options / frame-ancestors; checked 2026-09-27).
- SVG draw-in with `stroke-dasharray: 1` / `dashoffset: 1` and round caps paints a dot at the path ends while "undrawn" (zero-length dashes). `.note path` uses `dasharray: 1 2` + `dashoffset: 1.01` so the undrawn dash sits wholly before the path; keep that if the arrow CSS changes (the user saw the dot at the arrow tip before it drew).
- Section titles and pull questions use em-based offsets in their own (larger) font size: `top: 5em` on the 2em title put the sticky title 160px down, mid-section. Scale offsets by the element's font size.
- A body `##` directly followed by a `- ` list is still taken as the rail (Highlights). On a page with `game`, that rail is never rendered, so such a heading + list would silently vanish; put a paragraph between them or use `> ` lines.
- After clicking a nav button (Night, Index), focus stays on it, so arrow keys don't drive the gallery until it's clicked/focused (`onKey` requires gallery focus or pointer over it with nothing focused). Pre-existing behaviour.
- The bot's "Which model" set line in `knowledge.json` `instructions` names Google's Gemini as plain text. Change it if the provider switches (e.g. to Groq, section 15 of the questionnaire).
